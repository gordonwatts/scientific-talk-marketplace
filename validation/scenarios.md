# Acceptance scenarios

These scenarios check guidance and context behavior without creating a scientific deck or modifying the Davis talk. Automated structural checks complement a manual scenario walkthrough; neither proves how an installed agent or PowerPoint will behave. Use an isolated temporary talk workspace for exercises.

| Scenario | Input | Expected observable behavior |
| --- | --- | --- |
| New colloquium | Speaker supplies audience, duration, abstract and takeaways | Establish brief/status, confirm profiles, produce chapters for review before slide/graphic passes; do not invent metadata |
| No prior context | Read a populated starter with a current deck and an active slide ID | Recover current path/stage from three startup files, navigate only to affected outline/evidence, inspect deck before claiming its contents |
| Figure revision | Asset `A001` uses `P001` v2 Figure 3; v1 also exists | Resolve matching revision and original/usable file, retain caveat and units, cite matching source rather than whichever PDF was downloaded last |
| Focused slide edit | Outline `S007` maps to position 9; human deck text differs | Inspect current deck, preserve human edit, modify only affected material, refresh outline/status and inspect the result |
| Insert/reorder | A slide moves before `S007` | Stable IDs remain unchanged; current positions update; native numbering follows deck order; backups stay in Backup section |
| Missing source or PowerPoint | Paper unavailable or no native control path exists | Record gap accurately; continue independent preparation; do not claim a source downloaded or native deck checked |
| Future talk type | User requests a group update | Read only its selected profile or record audience/purpose/visual choices locally; do not open the colloquium style file or inherit its settings; preserve independent speaker choice |
| Another speaker | Presenter is not Gordon | Confirm profile choice and identity; do not silently apply Gordon's footer |
| Native default template | No supplied template; Gordon colloquium selected | Use PowerPoint built-in template/layouts, black master background and shared Office/theme formatting; preserve editable objects and automatic fields |
| Explanatory question | User asks what a project name means while reviewing a slide | Answer the question without replacing the slide's audience-facing message; put the explanation in notes if asked |
| Presenter notes | Notes contain repeated edits, "speaker requested" attribution and a useful evidence caveat | Produce current speaking notes with sources and the caveat; move revision history to workspace records rather than distancing the presenter from their content |
| Added subpoint | User adds modernization alongside library maintenance, and nests pilots beneath training | Preserve both software ideas as subpoints and keep pilots under training |
| Collaboration discussion | Only shared GPU use is known; user wants a collegial discussion | Avoid claiming a joint project or inventing workloads; use a specific supported connection or an open question, without an adversarial overlap slide or automatic shortlist |
| Working demonstration | User supplies comparison plots, workflow timings and short commentary | Give the evidence most of the space, keep the timing table editable, and retain the benchmark scope without filling the slide with implementation prose |
| Guidance retrospective | Substantial editing reaches a handoff; no upstream action authorized | Ask once about reviewing lessons and proposing a PR; do not change shared guidance or publish automatically |
| Authorized upstream contribution | User approves proposed lessons and asks for a PR | Find the original repository, apply shared versus speaker-specific guidance in the appropriate files, validate and open a scoped PR without asking again; do not merge or substitute an installed-cache edit |

Before claiming an installed-plugin test, install it separately through the client and observe the actual loaded skill and behavior. Before claiming a deck check, open/render it in PowerPoint and inspect it. Neither action is part of this package-authoring validation.
