# Three-pass outlining

Read the talk brief, audience profile and selected speaker content guidance. Keep a clear distinction between what appears on a slide, what the speaker says, and evidence supporting both.

## Pass 1: chapters

Develop `outline/chapters.md`: overall question/argument and a few intended takeaways, followed by chapters with stable IDs, purpose, prerequisite concepts, planned evidence, takeaway, transition, estimated minutes and a linked slide-outline path. Budget within the specified speaking time; distinguish speaking time from Q&A. Do not assume a universal slides-per-minute ratio.

Motivation, setup, results and conclusions must form an understandable argument for the selected audience. Mark unresolved scientific or audience questions. Review the chapter artifact with the speaker before expanding, unless the requested cadence permits continuing.

## Pass 2: slides

Create one Markdown slide-outline file per chapter using the [slide starter](../assets/starter/outline/slides/chapter.md). For each stable slide ID record:

- Working title, purpose, main-talk/backup placement, estimated speaking time.
- Audience-facing content and separately the spoken explanation/speaker notes.
- Takeaway, transition, scientific claim and its caveat.
- Evidence needed and known paper/source IDs or links.
- Visual requirement: what it should explain, potential figure or editable diagram, and constraints such as plot labels that must survive.

At this pass specify visual needs; do not confuse a proposed graphic with an obtained asset. A citation awaiting verification remains an open evidence need. Allow a sparse question, a figure-led explanation, or a dense exact prompt when its purpose justifies it. Do not impose equal density or force all titles into conclusions.

Read the sequence aloud in outline form. Check prerequisites before technical results, smooth chapter transitions, time estimates, and whether an outsider can state the main takeaway. Review before sourcing all graphics by default.

## Pass 3: graphics

Follow [sources and graphics](sources-and-graphics.md). For every slide, decide whether it uses an existing asset, a paper figure, native PowerPoint objects, generated artwork, or intentionally no graphic. Record selection/status, source revision, local asset path, important interpretation and layout/reveal needs in its outline entry. Missing assets remain visible gaps.

Show representative graphics and the completed per-slide mapping for review. A plan for a native diagram is a valid graphics-pass result; it need not be flattened into an image. Assemble editable PowerPoint chapter drafts after this pass is reviewed, unless directed otherwise.

## Iteration

Feedback can change an earlier pass. Update only the affected argument, slides, timing and graphics mapping, noting unresolved consequences. Keep the stable slide ID through wording and layout changes. Preserve backup material's scientific connection without counting it in main-talk timing.
